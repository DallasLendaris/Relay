# NIST SP 800-53 Rev. 5 moderate baseline: control gap map

> **Draft, pending review by SJSU counsel / the agency ISO.** Written by the engineering team from the code. It is a gap map, not an assessment, and it claims no compliance. Nothing is deployed and no AWS account exists, so "Built" means "in the code and the CDK templates", never "verified in a running system".

**As of:** branch `compliance-foundation` at commit `be6bc32` (the audit-fix round is merged; the [SSP](./system-security-plan.md) was written earlier, at `74acc5c`, so some of its "Fix planned" rows are now built and appear as Built or Partial here).

**Baseline source.** The control list is the NIST OSCAL profile `NIST_SP-800-53_rev5_MODERATE-baseline_profile.json`, release 5.2.0 (from `github.com/usnistgov/oscal-content`, fetched 2026-11-10): 287 controls and enhancements. Titles come from the 5.2.0 catalog in the same repository. Every one of the 287 is in a table below. Because the list came from NIST's machine-readable baseline, no row is a guess about baseline membership. Three things are marked in the Control column:

- **(no baseline)**: PM controls. 800-53B allocates none of them to a security baseline.
- **(privacy baseline)**: PT controls, which belong to the separate 800-53B privacy baseline, not the moderate security baseline.
- **(not in moderate)**: SR-4 (Provenance). It is in no 800-53B baseline. It is listed because this branch adds an SBOM.

Release 5.2.0 changed the moderate baseline compared with older copies: it includes SA-15(3) and MA-3(3). If the ISO assesses against an earlier release, those two rows may not apply. The [FIPS 199 draft](./fips199-categorization.md) proposes integrity and availability **high**. If the ISO agrees, the high baseline applies, which adds controls this map does not list (for example CA-8 penetration testing, AU-10, SC-24 and the high-only enhancements).

## How to read the columns

- **Category**
  - **Engineering**: code or AWS configuration that Relay builds.
  - **Organizational**: policy, people or process.
  - **Inherited (provider)**: AWS, Apple, Google or GitHub provides it. The evidence column says what the customer still owns, because inheritance is never complete.
- **Status**
  - Engineering rows are **Built** (in code, with evidence), **Partial** (some of it built, the gap is named) or **Missing**.
  - Organizational rows are **Drafted** (a document in `docs/compliance/` covers it, not adopted) or **Not started**.
  - Inherited rows say **Inherited**.
- **Evidence / gap.** A citation is a repo-relative path plus the construct, function or text it contains, written `path#name`. `node docs/compliance/check-evidence.mjs` checks that every cited file exists and contains the name, and that every Built row cites at least one. Finding IDs (SEC-C-4, PRIV-11, ...) are in [`docs/audit/findings.md`](../audit/findings.md). Questions (Q-n) are in the [compliance README](./README.md#decisions-and-questions).
- **Planned in this branch?** "Planned (compliance-foundation)" marks controls that work happening at the same time on this branch is expected to address. The status shown is still the status at `be6bc32`, before that work. The planned work is:
  - cdk-nag NIST 800-53 R5 checks on the CDK app: CM-6, and CA-7 in part.
  - Customer-managed KMS keys, TLS 1.2+ at the edge, FIPS endpoints and secret rotation: SC-8, SC-8(1), SC-12, SC-13, SC-28, SC-28(1), IA-5.
  - CI scanning (npm audit, CycloneDX SBOM, gitleaks, CodeQL): RA-5, SA-11, SR-4, CM-8.

  Re-check each of these rows once that work merges.

  **Update after the 2026-11 review** ([review-2026-11.md](./review-2026-11.md)). The 13 rows marked "Updated (compliance-foundation)" now show their status on `compliance-foundation` after that work merged; each row ends with its status at `be6bc32`. Every other row still shows its status at `be6bc32`.

  **Update on `b2-hardening`.** Rows whose evidence or status changed with the fixes for the review's open findings are marked "Updated (b2-hardening)"; [review-2026-11.md](./review-2026-11.md#resolved-in-b2-hardening) lists what each fix did and what remains.
