- **IAMNoInlinePolicy, DynamoDBInBackupPlan, RDSInBackupPlan, PITR/deletion protection (dev only), S3BucketReplicationEnabled, VPC public subnets, SecretsManagerRotationEnabled:** reasons match the code (sender SG: no ingress, egress TCP 443 only, `sender-stack.ts:201`; prod `deletionProtection: isProd` and `RemovalPolicy.SNAPSHOT`, `data-stack.ts:104-105`).
- **S3DefaultEncryptionKMS on access log buckets:** true, S3 server access log targets must use SSE-S3.

## C. Encryption, TLS, FIPS

### Producers and consumers of every encrypted resource

The resources are moved to CMKs at L1 (`encryption.ts` `encryptResources`), so CDK's L2 helpers add **no** `kms:` statements to any role or key policy. Each path therefore depends on the key policy alone. Checked one by one against the prod templates:
