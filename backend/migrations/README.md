# Database migrations

Every schema change is a SQL migration file in this folder. Migrations run from CI against Aurora Serverless v2 (PostgreSQL + PostGIS). Never change tables by hand in the AWS console, and never edit a migration that has already been merged; add a new one instead. The one exception is the grant list in `0011_roles.sql`: the migration runner applies it once (`schema_migrations`), but `infra/scripts/db-roles.ts` re-applies it on every run and it starts with `REVOKE ALL`, so a table added later must be listed there (as an optional row) **and** granted in its own migration (as `0015_alert_dropped_cells.sql` does). Listed in 0011 only, an existing database never gets the grant until db-roles runs; granted in the new migration only, the next db-roles run revokes it.
